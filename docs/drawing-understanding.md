# 图纸语义理解方案

这套 DXF 不能只按“26 张文件”理解，而应建立 **图纸 → 子视图 → 空间/轴网 → 构件 → 标注/索引 → 跨图引用** 的工程语义层。

## 1. 当前样本的实际观察

### 图纸角色

- J01–J04、J26：全局说明、构造/装饰、消防/防水、节能等约束性知识。
- J05：门窗一览表，适合作为门窗类型字典。
- J06–J12：主要定位图，包括楼层平面、屋顶、剖立面、立面、吊顶镜像平面。
- J13–J20、J25：卫生间、楼梯、钢梯、地坪等详图。
- J21–J24：进气塔、排气塔、引气塔的多层平面、立面和剖面。

### DXF 本身已有很强的语义信号

- 图层：`WALL`、`COLUMN`、`WINDOW`、`STAIR`、`AXIS`、`ROOF`、`HANDRAIL`、`LATRINE`、`吊顶` 等可直接映射为构件类别。
- 轴网块：`_AXISO` 的属性值直接给出 `1-A`、`2-3`、`3-M` 等轴号。
- 门窗/洞口编号：`FM甲1524`、`GM1824`、`GSM1024`、`LC1242`、`BYC0603` 等可以跨图匹配。
- J05 中可识别约 77 个门窗/洞口类型编号；J06 平面复用了约 50 个，J07 复用了约 31 个，J12 复用了约 19 个，说明“表格定义 → 平面实例”可以自动关联。
- J06 中存在“见1#楼梯详图”“见2#楼梯详图”“详见4#楼梯详图”“详见进气塔检修钢梯详图”等明确跨图引用。
- J21 中包含“钢梯详见进气塔检修钢梯详图”，可以直接连到 J20。

## 2. 需要建立的六层语义模型

### Sheet 图纸层

字段：图号、图名、比例、专业、图纸类别、全局/局部作用域。

### View 子视图层

一张 DXF 内经常不止一张图。例如：

- J06：一层平面图、1区二层平面图。
- J07：3区二层平面图、3区三层平面图、出屋面平面图、1-1剖面图。
- J21：多个标高平面图 + 东/西/南/北立面 + 剖面图。

因此第二阶段必须继续把每张 DXF 内部切成 View，并为每个 View 建立 bbox、类型、楼层/标高、区域。

### Spatial 空间层

识别：区域、楼层、轴网、房间、走道、设备间、楼梯间、塔体等。

房间名可由文字位置 + 封闭墙线/门洞关系确定。例如 J07/J12 中重复出现“数据采集间1”“数据分析间1”“走道”“女卫”等，后续可建立平面图与吊顶图的 `SAME_SPACE` 关系。

### Element 构件层

标准化构件类别：

- Wall / Column / Door / Window / Stair / Slab / Roof
- Handrail / Opening / EquipmentBase / CurtainWall
- Ceiling / Floor / Tower / SteelLadder

构件识别应综合：图层 + 块名 + 几何 + 附近文字，而不是只依赖一个字段。

### Annotation 标注层

包括尺寸、标高、轴号、房间名、构件编号、材料说明、详图索引、剖切索引、标准图集引用。

所有语义结论都应保留 `evidence`，例如原始文本、DXF handle、坐标、所在图层，便于人工核验。

### Relation 关系层

建议至少支持：

- `CONTAINS`：Sheet → View，View → Element/Space
- `LOCATED_ON_LEVEL` / `LOCATED_IN_ZONE`
- `AT_GRID`
- `BOUNDS`：Wall → Space
- `CONNECTS`：Door → Space
- `TYPE_DEFINED_BY`：门窗实例 → J05 类型表
- `DETAILED_BY`：平面中的楼梯/钢梯 → 对应详图
- `SECTION_OF` / `ELEVATION_OF` / `PLAN_OF`
- `SAME_SPACE`：不同图纸中的同一房间
- `APPLIES_TO`：说明/构造/节能条款 → 构件或整张图
- `REFERENCES_STANDARD`：构件/节点 → 17J925-1、22J403-1 等标准图集

## 3. 推荐的理解流水线

1. **结构化读取 DXF**：实体、图层、块、块属性、文字、尺寸、坐标。
2. **Sheet 分类**：先识别说明、表格、平面、立面、剖面、详图、专篇。
3. **View 切分**：用“子图标题文字 + 几何聚类 + 空白带”把单张 DXF 内的多个视图拆开。
4. **轴网重建**：读取 `_AXISO`，建立 X/Y 轴线及轴交点。
5. **构件归一化**：将天正/AutoCAD 图层和块映射到统一的 Element 类型。
6. **空间识别**：墙线闭合 + 房间文字 + 门连接，得到 Space。
7. **类型表关联**：优先解析 J05，将门窗代码变成可查询的类型字典。
8. **跨图引用解析**：解析“见…详图 / 详见…图纸 / 1-1 / 2-2 / 3-3”等索引，生成关系边。
9. **相同对象跨视图对齐**：用轴网、标高、构件编号、空间名对齐平面/立面/剖面/吊顶。
10. **生成语义图 JSON**，再交给前端 D3 和后续 AI 问答使用。

## 4. 不建议直接让大模型读原始几何

LLM 不应该直接消费几万条 LINE/LWPOLYLINE 坐标。正确流程是：

`DXF → 确定性解析/几何算法 → semantic_graph.json → LLM 推理`

这样模型回答“2#楼梯在哪几张图？”“FM甲1524 在哪些房间出现？”“数据采集间的平面与吊顶是什么关系？”时，可以给出可回溯到 DXF 实体的答案，而不是视觉猜测。

## 5. 下一阶段优先级

P0：View 子图自动切分；这是后续所有空间理解的前提。

P0：J05 门窗一览表结构化，并把门窗类型与 J06/J07/J12 等实例建立关系。

P1：J06/J07 的轴网、房间、墙/门/窗结构化。

P1：J06 → J14–J20、J21 → J20 等详图引用图谱。

P2：J07 与 J12 按楼层/房间建立平面图 ↔ 吊顶图映射；J06/J07 与 J09–J11 建立平面 ↔ 剖面/立面映射。

最终前端不只显示 CAD，而应支持点击一个房间/门窗/楼梯后，自动展示它关联的平面、立面、剖面、详图、类型表和说明条款。
